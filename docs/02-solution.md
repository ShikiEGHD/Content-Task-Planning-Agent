# 02 方案设计与技术取舍

## 当前状态

P1—P3 已完成离线实现；P4 文档和提交材料正在补齐。完整路线与备选方法见 [00-roadmap.md](00-roadmap.md)。

## 已确认技术栈

Python、LangGraph 1.2.10、argparse、dataclass、unittest、云端 API 与离线 Mock。云端使用 OpenAI Python SDK 直连 DeepSeek，模型为 deepseek-flash，关闭思考模式；OpenAI SDK 的本地安装和真实 API 调用仍待验证。

## 调用流程草案

输入校验 → LangGraph 模型决策节点 → 受控工具执行节点 → 更新状态与 Trace → 再次模型决策 → 完成/未完成。

工具为素材检索、脚本生成、成本估算、方案保存。模型决定继续、替代动作、修改计划或结束；程序检查输入、工具参数、预算、时间、依赖、保存条件与上限。

## 动态决策应满足

- 将工具返回及状态放回模型上下文。
- 超预算后由模型选择如何修改，而非程序直接指定廉价方案。
- 失败步骤保留真实状态，成功结果按依赖保留。
- 修改后重新估算，保存前再次校验。
- 两条以上真实模型路径体现不同结果导致不同后续动作。
- Mock 与云端适配器边界一致，但 Mock 不用于证明真实模型效果。

## 方法选择记录

| 决策 | 备选方法 | 推荐方向 | 用户最终选择/原因 |
|---|---|---|---|
| 云端接入 | 原生 SDK、兼容接口、结构化 JSON | 按可用供应商和实测决定 | DeepSeek 官方 API + OpenAI SDK 直连 |
| 工具路由 | 通用分发节点、独立业务节点 | 优先比较通用分发 | 通用模型节点 + 受控工具分发节点 |
| 脚本生成 | 本地模板、模型生成 | 最小版本优先比较本地模板 | 调用生成模型；Mock 只作离线替身 |
| 持久化 | JSON、SQLite、checkpoint + 幂等存储 | 按重复执行范围决定 | 本地 JSON + 幂等索引 + 自动版本 |
| CLI | argparse、Typer | 按依赖和开发成本比较 | argparse |
| 校验 | 标准库、Pydantic | 按契约复杂度比较 | dataclass + 手动校验 |
| 测试 | pytest、unittest | 按参数化与依赖权衡 | unittest |

优缺点详见路线文档，不能把推荐方向当作用户已批准。
